# Развёртывание агента на VPS клиента

Инструкция рассчитана на Ubuntu LTS и отдельный новый VPS. Команды и экран мастера могут меняться; перед production сверяйте их с официальной документацией Hermes.

Если человек раньше не работал с VPS, SSH и терминалом, используйте сначала `docs/BEGINNER-DEPLOYMENT.md`: там отдельно показаны действия для macOS и Windows, работа с GitHub, BotFather и проверка каждого шага.

## Этап 0. Подготовка

Нужно получить от клиента:

- IP-адрес VPS;
- отдельного пользователя с временным административным доступом;
- публичный SSH-ключ исполнителя, добавленный клиентом;
- токен отдельного Telegram-бота;
- числовые Telegram ID разрешённых пользователей;
- выбранный способ оплаты модели;
- заполненные `AGENTS.md` и `SOUL.md`.

Никогда не просите отправлять токены в обычном чате. Передавайте их через согласованный менеджер секретов или вводите непосредственно на сервере.

## Этап 1. Подготовить сервер

Подключитесь по SSH и создайте отдельного пользователя `agent` с минимально необходимыми правами. Обновите систему, включите автоматические security-обновления и firewall. Оставьте открытым SSH; для Telegram long polling входящий порт не требуется.

Проверки:

```bash
id
cat /etc/os-release
ss -lntup
```

До отключения входа по паролю откройте вторую SSH-сессию по ключу и убедитесь, что она работает. Не блокируйте root/пароль, пока ключевой вход не проверен.

## Этап 2. Установить Hermes из официального источника

Войдите пользователем `agent`. Просмотрите установочный скрипт перед запуском, затем используйте актуальную официальную команду:

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | less
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

Перезагрузите оболочку и проверьте установку:

```bash
source ~/.bashrc
hermes --help
hermes doctor
```

## Этап 3. Настроить модель

Запустите мастер:

```bash
hermes setup
```

Выберите провайдера, который согласовал и оплачивает клиент. Условия подписки пользовательского чат-продукта не всегда разрешают серверную автоматизацию; используйте только явно поддерживаемый Hermes способ авторизации и условия выбранного провайдера. Зафиксируйте модель, лимит расходов и ответственного за биллинг.

Для пошагового выбора между Claude/Anthropic и ChatGPT/Codex используйте раздел «Часть 9» в `docs/BEGINNER-DEPLOYMENT.md`. Установка VPS, Telegram, правил и скиллов от выбранной модели не меняется.

Сначала проверьте обычный диалог в терминале. Не подключайте Telegram и внешние инструменты, пока базовый ответ не работает.

## Этап 4. Установить собственную личность

Скопируйте заполненный файл:

```bash
cp templates/SOUL.md ~/.hermes/SOUL.md
mkdir -p ~/client-agent-workspace
cp AGENTS.md ~/client-agent-workspace/AGENTS.md
```

Укажите рабочую папку через актуальную команду конфигурации Hermes или мастер настройки. Запустите Hermes из этой папки и задайте контрольные вопросы:

- «Как тебя зовут и какую компанию ты представляешь?»
- «Какие действия требуют подтверждения?»
- «Кто создал используемое открытое ПО?»

Ожидаемый результат: агент использует бренд клиента, соблюдает границы и не заявляет ложное авторство.

## Этап 5. Подключить Telegram

Клиент создаёт нового бота через `@BotFather`. Получите числовые ID пользователей и запустите:

```bash
hermes gateway setup
```

Выберите Telegram, введите токен и включите allowlist только для согласованных ID. Затем проверьте в foreground:

```bash
hermes gateway run
```

Отправьте боту тестовое сообщение. Остановите foreground-процесс перед запуском службы: один токен не должен одновременно опрашиваться двумя копиями.

## Этап 6. Запустить как службу

Для headless VPS официальный проект рекомендует системную службу:

```bash
sudo hermes gateway install --system
sudo hermes gateway start --system
sudo hermes gateway status --system
```

Проверьте журналы:

```bash
journalctl -u hermes-gateway -n 100 --no-pager
```

Имя службы может отличаться для отдельного профиля. Для диагностики используйте `hermes gateway status --deep` и `hermes doctor`.

## Этап 7. Подключать инструменты по одному

Начните без MCP. Для каждого нового API/MCP оформите карточку: владелец, цель, доступные данные, разрешённые действия, секрет, лимит затрат, способ отключения. Подключите один инструмент, проверьте тестовый сценарий и только затем переходите к следующему.

Секреты храните в `~/.hermes/.env` с правами `600`, а не в Git:

```bash
chmod 600 ~/.hermes/.env
```

Не подключайте личные подписки или учебные библиотеки исполнителя к экземпляру клиента.

## Этап 8. Проверка после перезагрузки

```bash
sudo reboot
```

После возвращения VPS проверьте:

```bash
sudo hermes gateway status --system
journalctl -u hermes-gateway -n 100 --no-pager
```

Затем проверьте Telegram, allowlist, чтение только разрешённых данных, подтверждение опасного действия и отсутствие секретов в ответах/журналах.

## Этап 9. Передача клиенту

Передайте клиенту ссылку на приватный репозиторий, схему, перечень сервисов и ежемесячных расходов, инструкцию остановки, процедуру восстановления и дату следующего обновления. Удалите временный SSH-ключ исполнителя либо оформите поддержку отдельным соглашением.
