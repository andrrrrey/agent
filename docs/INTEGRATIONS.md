# Карта бизнес-интеграций

## Приоритеты

| Контур | Источник | Первая версия | Следующий уровень |
|---|---|---|---|
| Продажи | amoCRM, Bitrix24, HubSpot или другая CRM | чтение сделок и задач | подтверждённые изменения полей |
| Маркетинг | GA4, Яндекс.Метрика, рекламные кабинеты | отчёт по источникам и воронке | создание черновика гипотез/кампаний |
| Знания | Drive, Notion, корпоративное хранилище | ответы с цитатами | предложения обновлений базы |
| Коммуникации | Telegram, email, календарь | чтение/черновики | отправка после подтверждения |
| Автоматизация | n8n или собственные webhooks | наблюдение за workflow | запуск утверждённых сценариев |
| Контент | CMS и социальные платформы | экспорт готового пакета | публикация после подтверждения |
| Управление | таблицы, BI, финансы | read-only KPI | утверждённые записи/планы |

## Безопасный порядок подключения

1. Создайте карточку интеграции.
2. Определите владельца данных и законное основание обработки.
3. Создайте отдельный аккаунт/ключ для агента.
4. Выдайте минимальные read-only права.
5. Ограничьте MCP только нужными инструментами.
6. Проверьте пять тестовых запросов и два запроса, которые должны быть запрещены.
7. Включайте запись отдельным решением клиента.
8. Настройте журнал, лимит и процедуру отзыва доступа.

## MCP в Hermes

Используйте встроенный каталог как отправную точку:

```bash
hermes mcp catalog
hermes mcp
```

Перед установкой прочитайте `source` и команды установки manifest. После подключения оставьте только нужные tools через include/exclude. Для систем с общим состоянием не включайте параллельные write-вызовы.

## n8n

n8n полезен как оркестратор детерминированных шагов: webhook, преобразование данных, повтор, очередь и журнал. Hermes может анализировать и принимать решения, а n8n — надёжно выполнять утверждённый маршрут. Начинайте с read-only инструментов наблюдения за workflow; активацию и изменение сценариев выдавайте отдельно.

## Что не подключать по умолчанию

- платежи и банковские кабинеты;
- удаление CRM/документов;
- личный Telegram user-аккаунт;
- один write-токен для нескольких клиентов или профилей;
- автоматическую публикацию без staging/preview;
- MCP неизвестного происхождения без просмотра исходника и manifest.
