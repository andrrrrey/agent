# Установка и запуск бизнес-агента: инструкция для начинающих

Эта инструкция предназначена для человека, который умеет пользоваться браузером, но раньше почти не работал с серверами и командной строкой.

Результат: Hermes Agent будет круглосуточно работать на Ubuntu‑VPS клиента, принимать сообщения через Telegram и использовать правила, знания и скиллы из приватного репозитория.

## Самое важное перед началом

macOS или Windows — это ваш личный компьютер, с которого вы настраиваете систему. Сам агент устанавливается не на MacBook и не на Windows-компьютер, а на удалённый Linux-сервер клиента — VPS. Благодаря этому агент продолжает работать, когда ваш компьютер выключен.

В инструкции используются три пометки:

- **На своём компьютере** — действие выполняется на Mac или Windows;
- **На сервере** — команда вводится после подключения к VPS;
- **На сайте** — действие выполняется в браузере.

Не вставляйте в команды символы приглашения вроде `$`, `%` или `agent@server:~$`. Копируйте только содержимое серого блока.

## Что подготовить

До установки должны быть готовы:

- VPS с Ubuntu LTS, IP-адресом и доступом администратора;
- приватный GitHub-репозиторий проекта;
- GitHub-аккаунт установщика, добавленный в репозиторий;
- отдельный Telegram-бот клиента;
- числовой Telegram ID владельца;
- аккаунт поддерживаемого провайдера модели и согласованный способ оплаты;
- заполненные сведения о компании, роли и разрешённых действиях агента;
- менеджер паролей для токенов и ключей.

Не присылайте токен Telegram, ключ модели или пароль VPS в Telegram, электронном письме, GitHub и обычном чате. Вводите секрет непосредственно в мастер настройки на сервере или передавайте через согласованный менеджер секретов.

# Часть 1. Получить доступ к приватному репозиторию

## Шаг 1. Сообщить владельцу свой GitHub-логин

**На сайте:**

1. Откройте [github.com](https://github.com/).
2. Нажмите `Sign in` и войдите в свой аккаунт. Если аккаунта нет, нажмите `Sign up` и зарегистрируйтесь.
3. Нажмите на фотографию профиля справа сверху.
4. Ваш логин показан рядом с фотографией и начинается не с `@`. Скопируйте его.
5. Отправьте владельцу репозитория только этот логин или почту GitHub. Пароль отправлять нельзя.

Владелец открывает репозиторий → `Settings` → `Collaborators` → `Add people`, находит логин и отправляет приглашение.

## Шаг 2. Принять приглашение

**На сайте:**

1. Откройте письмо от GitHub или страницу уведомлений GitHub.
2. Нажмите `View invitation`.
3. Нажмите `Accept invitation`.
4. Откройте приватный репозиторий и убедитесь, что видны файлы `README.md`, `AGENTS.md`, папки `docs`, `skills` и `knowledge`.

Если GitHub показывает страницу `404`, чаще всего приглашение ещё не принято или вы вошли не в тот аккаунт.

# Часть 2. Создать Telegram-бота и узнать свой ID

## Шаг 3. Создать бота

**На своём компьютере или телефоне в Telegram:**

1. В поиске Telegram найдите официальный аккаунт `@BotFather`.
2. Проверьте точное имя: `BotFather` и username `@BotFather`.
3. Нажмите `Start` или отправьте `/start`.
4. Отправьте команду `/newbot`.
5. Введите отображаемое имя, например `Ассистент компании Альфа`.
6. Придумайте техническое имя, которое обязательно заканчивается на `bot`, например `alpha_business_helper_bot`.
7. BotFather пришлёт токен — длинную строку с двоеточием. Сразу сохраните её в менеджере паролей.

Токен равен паролю от бота. Если он попал в чат, скриншот или GitHub, его нужно отозвать у BotFather и выпустить новый.

## Шаг 4. Узнать числовой Telegram ID

Username вида `@ivan` не подходит. Hermes нужен числовой ID.

1. В Telegram найдите `@userinfobot`.
2. Нажмите `Start`.
3. Скопируйте число из ответа, например `123456789`.
4. Сохраните его рядом с названием проекта, но не публикуйте в открытом репозитории.

# Часть 3. Подключиться к VPS

У вас должны быть IP-адрес сервера, имя пользователя и пароль либо SSH-ключ. В примерах ниже:

- `203.0.113.10` — пример IP, его нужно заменить на настоящий;
- `root` — первоначальный администратор сервера;
- `agent` — отдельный пользователь, под которым будет работать агент.

## Вариант A: macOS

**На своём Mac:**

1. Нажмите `Command + Space`.
2. Введите `Терминал` или `Terminal`.
3. Нажмите Enter.
4. В открывшемся окне введите, заменив IP:

```bash
ssh root@203.0.113.10
```

5. При первом подключении может появиться вопрос `Are you sure you want to continue connecting?`. Сверьте fingerprint сервера с данными хостинга, затем введите `yes` и нажмите Enter.
6. Введите пароль VPS и нажмите Enter. При вводе пароля символы не отображаются — это нормально.

## Вариант B: Windows 10 или 11

**На своём компьютере:**

1. Нажмите кнопку `Пуск`.
2. Введите `PowerShell`.
3. Откройте `Windows PowerShell` или приложение `Терминал` с вкладкой PowerShell.
4. Введите, заменив IP:

```powershell
ssh root@203.0.113.10
```

5. При первом подключении сверьте fingerprint, введите `yes` и нажмите Enter.
6. Введите пароль VPS и нажмите Enter. Пароль визуально не появляется — это нормально.

## Как понять, что подключение состоялось

Слева в строке появится что-то похожее на:

```text
root@server:~#
```

Теперь все команды выполняются **на сервере**, пока вы не введёте `exit` или не закроете окно.

### Частые ошибки подключения

- `Connection timed out` — неверный IP, VPS выключен или SSH закрыт firewall хостинга;
- `Connection refused` — SSH-служба на сервере не запущена или используется другой порт;
- `Permission denied` — неверны имя пользователя, пароль или SSH-ключ;
- команда `ssh` не найдена в Windows — откройте `Параметры` → `Приложения` → `Дополнительные компоненты` → `Добавить компонент`, найдите `OpenSSH Client` и установите его.

При этих ошибках не повторяйте пароль десятки раз: проверьте данные в панели VPS-провайдера.

# Часть 4. Создать отдельного пользователя агента

Не запускайте бизнес-агента постоянно от имени `root`.

## Шаг 5. Создать пользователя

**На сервере под root:**

```bash
adduser agent
```

Сервер попросит придумать пароль и несколько необязательных полей. Пароль сохраните в менеджере паролей. Необязательные поля можно пропускать клавишей Enter. В конце подтвердите данные.

Добавьте пользователя в группу администраторов:

```bash
usermod -aG sudo agent
```

Переключитесь на него:

```bash
su - agent
```

Проверьте:

```bash
whoami
```

Ожидаемый ответ:

```text
agent
```

Все следующие действия выполняйте от пользователя `agent`, если в инструкции явно не написано иначе.

## Шаг 6. Настроить вход по SSH-ключу

Пароль можно использовать для первого входа, но для постоянной работы безопаснее SSH-ключ.

### macOS

**Откройте второе окно Терминала на своём Mac** и выполните:

```bash
ssh-keygen -t ed25519 -C "client-agent-access"
```

На вопрос о пути нажмите Enter. Для ключа рекомендуется задать парольную фразу и сохранить её в менеджере паролей.

Покажите публичную часть ключа:

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируйте всю строку, начинающуюся с `ssh-ed25519`.

### Windows

**Откройте второе окно PowerShell на своём компьютере** и выполните:

```powershell
ssh-keygen -t ed25519 -C "client-agent-access"
```

На вопрос о пути нажмите Enter. Затем покажите публичную часть:

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

Скопируйте всю строку, начинающуюся с `ssh-ed25519`.

### Добавить ключ на сервер

Вернитесь в первое окно, где вы уже подключены к VPS как `agent`.

**На сервере:**

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys
```

Откроется текстовый редактор `nano`:

1. Вставьте скопированную строку публичного ключа.
2. Нажмите `Ctrl + O`, затем Enter — это сохранение.
3. Нажмите `Ctrl + X` — это выход.

Установите правильные права:

```bash
chmod 600 ~/.ssh/authorized_keys
```

Не закрывая текущую сессию, откройте ещё одно окно Terminal или PowerShell и проверьте вход:

```bash
ssh agent@203.0.113.10
```

Только после успешного входа по ключу продолжайте установку. Не отключайте парольный или root-доступ, пока ключ не проверен во второй сессии.

# Часть 5. Подготовить Ubuntu-сервер

## Шаг 7. Проверить операционную систему

**На сервере под пользователем `agent`:**

```bash
cat /etc/os-release
```

В выводе должно быть `Ubuntu`. Если сервер использует другую систему, остановитесь и обратитесь к техническому специалисту: команды ниже рассчитаны на Ubuntu LTS.

## Шаг 8. Установить обновления

```bash
sudo apt update
sudo apt upgrade -y
```

При запросе введите пароль пользователя `agent`. Выполнение может занять несколько минут.

## Шаг 9. Включить базовый firewall

Сначала разрешите SSH, иначе можно потерять доступ к серверу:

```bash
sudo apt install -y ufw
sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status
```

На вопрос о включении firewall ответьте `y`. В результате должны появиться слова `Status: active` и разрешение `OpenSSH`.

Для Telegram long polling отдельный входящий порт открывать обычно не требуется.

# Часть 6. Подключить приватный GitHub-репозиторий

Для VPS безопаснее использовать отдельный read-only deploy key. Такой ключ открывает серверу только этот репозиторий.

## Шаг 10. Создать GitHub-ключ на VPS

**На сервере под пользователем `agent`:**

```bash
ssh-keygen -t ed25519 -C "client-agent-vps"
```

На вопрос о пути нажмите Enter. Для unattended-обновлений ключ обычно оставляют без парольной фразы; компенсируйте это минимальными правами VPS и read-only доступом только к одному репозиторию.

Если программа спрашивает, перезаписать ли уже существующий ключ, ответьте `n` и остановитесь: существующий ключ нельзя затирать без проверки специалиста.

Покажите публичный ключ:

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируйте всю строку. Закрытый файл `~/.ssh/id_ed25519` никогда никому не отправляйте.

## Шаг 11. Добавить deploy key в GitHub

Это делает владелец репозитория.

**На сайте GitHub:**

1. Откройте приватный репозиторий.
2. Нажмите вкладку `Settings`.
3. Слева найдите `Deploy keys`.
4. Нажмите `Add deploy key`.
5. В поле `Title` введите понятное имя, например `VPS клиента Альфа`.
6. В поле `Key` вставьте публичный ключ.
7. Не включайте `Allow write access`: серверу достаточно чтения.
8. Нажмите `Add key` и подтвердите действие в GitHub.

Если у установщика нет доступа к `Settings`, он отправляет публичный ключ владельцу репозитория. Отправлять нужно только строку `.pub`, не закрытый ключ.

## Шаг 12. Скачать проект на сервер

**На сервере:**

Проверьте соединение с GitHub:

```bash
ssh -T git@github.com
```

При первом подключении сверяйте fingerprint GitHub с опубликованным GitHub fingerprint и только затем отвечайте `yes`. Сообщение о том, что shell-доступ не предоставляется, нормально: важно, чтобы аутентификация была успешной.

Скачайте проект:

```bash
git clone git@github.com:andrrrrey/agent.git ~/client-agent-starter
cd ~/client-agent-starter
ls
```

Должны быть видны `README.md`, `AGENTS.md`, `config`, `docs`, `knowledge`, `skills` и `templates`.

Если появилось `Repository not found`, проверьте адрес репозитория и deploy key. Если репозиторий переименован, замените URL на актуальный.

# Часть 7. Заполнить правила и знания клиента

Удобнее редактировать небольшие текстовые файлы прямо на сайте GitHub.

## Шаг 13. Заполнить основные файлы

**На сайте GitHub:**

1. Откройте файл `AGENTS.md`.
2. Нажмите значок карандаша `Edit this file`.
3. Замените все конструкции вида `{{...}}` реальными данными клиента.
4. Нажмите `Commit changes`.
5. Введите понятное описание, например `Настроить правила агента для компании Альфа`.
6. Подтвердите сохранение.

Повторите для файлов:

- `templates/SOUL.md` — имя, роль и стиль общения;
- `knowledge/COMPANY.md` — проверенные сведения о компании;
- `knowledge/OFFERS.md` — продукты, услуги и ограничения;
- `knowledge/POLICIES.md` — правила, которые агент обязан соблюдать;
- `knowledge/ICP.md` — целевая аудитория, если агент работает с маркетингом или продажами;
- `knowledge/BRAND-VOICE.md` — стиль сообщений компании.

Не помещайте в эти файлы пароли, API-ключи, токены, банковские данные и лишние персональные данные.

## Шаг 14. Получить изменения на VPS

**На сервере:**

```bash
cd ~/client-agent-starter
git pull
```

Проверьте, остались ли незаполненные плейсхолдеры:

```bash
grep -R "{{" AGENTS.md templates/SOUL.md knowledge
```

Если команда ничего не показала, основные плейсхолдеры заполнены. Если строки появились, вернитесь на GitHub и заполните их.

# Часть 8. Установить Hermes Agent

## Шаг 15. Просмотреть и запустить официальный установщик

**На сервере под пользователем `agent`:**

Сначала откройте установочный сценарий для просмотра:

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | less
```

Клавиши со стрелками прокручивают текст, `q` закрывает просмотр.

Запустите официальный установщик:

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

После завершения перечитайте настройки терминала:

```bash
source ~/.bashrc
```

Проверьте установку:

```bash
hermes --help
hermes doctor
```

Если `hermes: command not found`, выйдите с VPS командой `exit`, подключитесь снова как `agent` и повторите `hermes --help`.

# Часть 9. Настроить модель и проверить обычный диалог

## Шаг 16. Запустить мастер Hermes

**На сервере:**

```bash
hermes setup
```

Мастер может меняться вместе с версией Hermes. Читайте каждый вопрос на экране и выбирайте только того провайдера, которого согласовал и оплачивает клиент. Для перемещения обычно используются стрелки, для выбора — Enter.

Если мастер просит API-ключ:

1. Откройте менеджер паролей.
2. Скопируйте ключ.
3. Вставьте его непосредственно в терминал.
4. Не сохраняйте ключ в GitHub и не отправляйте скриншот терминала.

Зафиксируйте лимит расходов в кабинете провайдера модели. Подписка на пользовательский чат и API-доступ могут быть разными услугами; используйте только поддерживаемый Hermes способ авторизации.

## Шаг 17. Подключить правила проекта

**На сервере:**

```bash
cp ~/client-agent-starter/templates/SOUL.md ~/.hermes/SOUL.md
mkdir -p ~/client-agent-workspace
cp ~/client-agent-starter/AGENTS.md ~/client-agent-workspace/AGENTS.md
cp -R ~/client-agent-starter/knowledge ~/client-agent-workspace/knowledge
hermes config set terminal.cwd /home/agent/client-agent-workspace
```

## Шаг 18. Установить стартовые скиллы

Не обязательно устанавливать все скиллы. Для первого теста возьмите только те, которые относятся к согласованной задаче клиента.

Пример безопасного стартового набора:

```bash
mkdir -p ~/.hermes/skills/business
cp -R ~/client-agent-starter/skills/knowledge-base-answer ~/.hermes/skills/business/
cp -R ~/client-agent-starter/skills/customer-reply-draft ~/.hermes/skills/business/
cp -R ~/client-agent-starter/skills/business-daily-brief ~/.hermes/skills/business/
cp -R ~/client-agent-starter/skills/safe-autonomous-work ~/.hermes/skills/business/
hermes skills list
```

Для агента продаж можно дополнительно установить `lead-qualification`, `lead-followup-sequence` и `sales-pipeline-control`. Полный каталог описан в `docs/SKILLS.md`.

## Шаг 19. Проверить агента в терминале

```bash
cd ~/client-agent-workspace
hermes
```

Задайте вопросы:

1. `Как тебя зовут и какую компанию ты представляешь?`
2. `Какие действия ты можешь выполнять самостоятельно?`
3. `Какие действия требуют подтверждения?`
4. `Назови услуги компании и укажи источник.`
5. `Отправь клиенту сообщение без моего подтверждения.`

В последнем тесте агент должен отказаться от отправки без подтверждения. Чтобы завершить терминальный сеанс, используйте показанную Hermes команду выхода или нажмите `Ctrl + C`.

Не переходите к Telegram, если агент путает компанию, выдумывает услуги или игнорирует границы.

# Часть 10. Подключить Telegram

## Шаг 20. Запустить мастер gateway

**На сервере:**

```bash
hermes gateway setup
```

В мастере:

1. Выберите Telegram.
2. Вставьте токен от BotFather.
3. Введите числовой Telegram ID владельца.
4. Выберите режим allowlist — доступ только указанным пользователям.
5. Не включайте open access.
6. Завершите мастер и сохраните настройки.

Если будет предложен DM pairing вместо allowlist, для первого production-клиента предпочтительнее явный список разрешённых ID.

## Шаг 21. Первый запуск в тестовом режиме

**На сервере:**

```bash
hermes gateway run
```

Не закрывайте это окно. Теперь:

1. Откройте созданного бота в Telegram.
2. Нажмите `Start`.
3. Отправьте `Привет. Представься и назови свои границы.`
4. Убедитесь, что ответ соответствует клиенту.
5. Попросите второго, не добавленного в allowlist человека написать боту. Агент не должен дать ему рабочий доступ.

Вернитесь в терминал и нажмите `Ctrl + C`, чтобы остановить тестовый gateway. Это обязательно: нельзя одновременно запускать две копии gateway с одним Telegram-токеном.

# Часть 11. Запустить агента круглосуточно

## Шаг 22. Установить системную службу

**На сервере:**

```bash
sudo hermes gateway install --system
sudo hermes gateway start --system
sudo hermes gateway status --system
```

В нормальном результате должны быть слова о том, что gateway service запущена или `active (running)`.

Посмотрите последние сообщения службы:

```bash
journalctl -u hermes-gateway -n 100 --no-pager
```

Не публикуйте полный журнал: в нём могут встречаться внутренние данные. Для обращения за помощью копируйте только относящийся к ошибке фрагмент и предварительно удаляйте секреты.

## Шаг 23. Проверить автозапуск после перезагрузки

Предупредите клиента о короткой недоступности и выполните:

```bash
sudo reboot
```

Соединение закроется — это нормально. Подождите одну-две минуты и снова подключитесь со своего компьютера:

```bash
ssh agent@203.0.113.10
```

Затем **на сервере** проверьте:

```bash
sudo hermes gateway status --system
hermes gateway status --deep --system
hermes doctor
```

Отправьте тестовое сообщение в Telegram. Агент должен ответить без открытого окна терминала на вашем компьютере.

## Команды владельца

Показать состояние:

```bash
sudo hermes gateway status --system
```

Перезапустить один основной gateway:

```bash
sudo hermes gateway restart --system
```

Остановить:

```bash
sudo hermes gateway stop --system
```

Запустить:

```bash
sudo hermes gateway start --system
```

Провести диагностику:

```bash
hermes gateway status --deep --system
hermes doctor
```

Не применяйте флаги `--all`, не удаляйте PID/lock-файлы и не перезагружайте сервер как универсальный способ исправления ошибки.

# Если что-то не работает

## Telegram-бот не отвечает

**На сервере:**

```bash
sudo hermes gateway status --system
hermes gateway status --deep --system
journalctl -u hermes-gateway -n 100 --no-pager
```

Проверьте по порядку:

1. Служба запущена.
2. Введён правильный токен.
3. Ваш числовой ID находится в allowlist.
4. Не запущена вторая копия `hermes gateway run`.
5. Токен не был отозван через BotFather.
6. У VPS есть доступ в интернет.

## Агент отвечает, но использует старые правила

Получите последнюю версию репозитория и повторно скопируйте файлы:

```bash
cd ~/client-agent-starter
git pull
cp templates/SOUL.md ~/.hermes/SOUL.md
cp AGENTS.md ~/client-agent-workspace/AGENTS.md
cp -R knowledge/. ~/client-agent-workspace/knowledge/
sudo hermes gateway restart --system
```

Начните новую сессию в Telegram: существующая сессия может сохранять старый контекст.

## `git pull` просит логин и пароль

Вероятно, проект был скачан по HTTPS. Не вводите обычный пароль GitHub: парольная аутентификация Git для GitHub не поддерживается. Настройте deploy key по части 6 и используйте SSH-адрес репозитория.

## Закончились деньги или превышен лимит модели

Не меняйте провайдера на личный аккаунт установщика. Сообщите владельцу, проверьте биллинг и после согласования обновите способ авторизации через официальный мастер Hermes.

## Когда нужно остановиться и позвать специалиста

- появились сообщения о взломе, утечке токена или неизвестном входе;
- закончилось место на диске;
- служба постоянно перезапускается;
- VPS не доступен по SSH;
- неизвестный пользователь получил доступ к боту;
- требуется менять firewall, systemd, права, сеть или удалять данные;
- две обычные попытки диагностики не выявили причину.

Не скрывайте сбой и не продолжайте случайно выполнять команды из интернета.
