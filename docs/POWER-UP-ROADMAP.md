# Усиление бизнес-агента

Сильный агент — это не чат с большим числом скиллов, а замкнутый управляемый цикл:

```text
данные → анализ → рекомендация → подтверждение → действие → измерение → улучшение
```

## Целевой контур

### 1. Бизнес-память

Заполните файлы `knowledge/`: компания, аудитория, продукты, голос бренда, определения метрик и правила. Без этого агент будет звучать убедительно, но давать общие советы.

### 2. Источники данных

Подключайте системы сначала только на чтение: CRM, аналитика сайта, рекламные кабинеты, база знаний, календарь, почта, документы и таблицы. Каждый источник оформляется карточкой из `templates/INTEGRATION-CARD.md`.

### 3. Рабочие контуры

- Маркетинг: исследование → гипотеза → производство → согласование → публикация → измерение.
- Продажи: лид → квалификация → касания → сделка → контроль SLA → прогноз → winback.
- Клиентский сервис: обращение → ответ/эскалация → решение → причина → обновление базы знаний.
- Управление: встречи/данные → сводка → решение → задача → контроль результата.

### 4. Автоматизация

После ручной проверки процесса добавляйте расписание и n8n/webhooks. Фоновая задача должна быть идемпотентной, иметь лимит, журнал и безопасный повтор. Автоматические публикации, рассылки и изменения CRM включаются только после этапа черновиков.

### 5. Измерение

Для каждого процесса до запуска зафиксируйте базовую линию: время, стоимость, ошибки, конверсию и выручку. После запуска сравнивайте те же определения, а не субъективное впечатление.

## Очерёдность внедрения

### Этап A — наблюдает

Агент читает согласованные данные и формирует сводки: воронка, сделки, загрузка, вопросы клиентов, контент и KPI. Риск минимален, ценность уже измерима.

### Этап B — предлагает

Агент создаёт черновики ответов, задач, КП, follow-up и контента. Человек подтверждает всё внешнее.

### Этап C — выполняет с подтверждением

После стабильных тестов агент может обновлять отдельные поля CRM, создавать задачи и ставить события. Перед каждым внешним действием показывается diff.

### Этап D — работает по расписанию

Ежедневные и недельные отчёты, мониторинг, напоминания и read-only проверки запускаются автоматически. Для фоновых заданий опасные действия запрещены.

### Этап E — команда профилей

При достаточном объёме создаются отдельные профили: `researcher`, `marketer`, `sales-analyst`, `operations`, а центральный агент управляет задачами. Начинайте с read-only ролей; не давайте нескольким профилям общие write-токены.

## Главный принцип комплектации

На одного клиента устанавливайте не все скиллы, а только набор под выбранные процессы. Большой каталог — витрина возможностей; активный комплект должен быть небольшим и проверяемым.
